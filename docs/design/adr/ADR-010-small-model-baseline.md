# ADR-010 配置模型逐点实测与分级降级

- 状态：Accepted
- 日期：2026-09-17
- 修订：2026-10-09，取消固定参数量、量化与本地部署要求；保留逐点准入与降级约束
- 关联：需求 1.3、1.4、5.2、NFR-23~27；设计 DD-1.1、DD-12

## 背景

应用默认**本地 / 内网私有部署**，模型默认关闭。启用时使用显式配置且授权的 OpenAI 兼容端点，部署位置可为本地、内网或外部服务，调用范围遵守需求 10.11。

初版曾将 27B 级本地模型列为目标基线；2026-10-09 按使用方要求取消该规格限制，文件路径与编号保留便于追溯。配置模型仍可能输出错误、缺少置信度、限流或不可用，不能用参数量、部署位置或 HTTP 成功推断任务质量。

规则兜底保障模型关闭时可运行，逐点真实评测决定模型接管范围；两者都必须在发行默认构建中可核验。

## 决策

1. **使用显式配置模型逐点评测**，不限定参数量、量化或部署位置；未达标、未覆盖或基线身份失配的点走规则；
2. 决策点**分级**（需求 5.2.3 / DD-12.3）：`auto`（自动采用）/ `confirm`（需人工确认）/
   `manual`（必须人工）；
3. **未知或低置信不静默采用**：缺失置信度或低于阈值默认走规则并进裁决队列；替代准入依据须显式配置、可审计且重新实测，不得仅将阈值置 0 或捏造分数（验收 39）；
4. **模型不可用必须可运行**：走规则默认值 + 标记「待确认」，**构建不得失败**（NFR-26）；
5. **保持配置兼容与数据边界**：保留历史路由标识 `small_model` / `optional_large_model`，不将其解释为规格约束；禁止隐式云端回退和 tracing 外发，关闭模型时零模型请求。

## 备选方案与取舍

| 方案 | 优点 | 代价 | 结论 |
| --- | --- | --- | --- |
| 固定模型规模与本地部署 | 可限定一套测试环境 | 限制使用方已有服务，规格仍不能证明任务质量 | 取消 |
| 完全不使用模型 | 完全确定，无模型依赖 | 只能使用规则和人工判断 | 保留为降级路径 |
| **配置模型基线 + 分级降级** | 使用方可选授权服务，规则保障质量下限 | 需候选集、逐点实测、准入依据与出口取证 | 采纳 |

## 后果

### 正面

- `DF_MODEL_ENABLED=false` 时全链路仍可跑通，产出完整（只是决策项减少）；
- 模型服务抖动不会把构建变成失败——只是多几条待确认。

### 负面（明确接受的代价）

- 需要维护"规则默认值"这套兜底知识，它是模型能力的下限保障；
- 阈值与接管比例依赖**验收 37–41 的真实数据**，不能凭模型名称推断。

### 需要后续跟进

- TASK-P0-17：发行默认阶段实际调用配置模型，补齐逐点基线与缺置信度准入，实测后登记接管范围；日期与依赖见 [路线图](../../../ROADMAP.md)；
- 受限解码按端点能力启用；不支持时使用字段约束、Schema 校验、有限重试与规则兜底，并在设置页显示能力；
- 系统级运行期网络记录须核对授权端点、tracing 禁用与关闭模型零请求；HTTP 客户端日志不足以证明全部出口。
