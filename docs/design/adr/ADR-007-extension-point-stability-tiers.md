# ADR-007 五类扩展点的稳定度分级

- 状态：Accepted
- 日期：2026-09-17
- 关联：需求 4.5；设计 DD-1.1、DD-3.1、docs/spec/

## 背景

开源项目必须回答一个问题：**外部可以依赖什么，依赖到什么程度**。

两种失败模式：

- 承诺过宽（什么都可以依赖）→ 每个内部实现都变成兼容包袱，改不动；
- 承诺过窄（什么都不保证）→ 使用者不敢基于它做集成，生态起不来。

## 决策

把扩展点分为五类，逐类给出稳定度承诺；级别越高，允许的变更方式越严格：

| # | 扩展点 | 稳定度 | 允许的变更 |
| --- | --- | --- | --- |
| 1 | 模板包契约 | Stable | 增加可选字段；删除 / 改名走弃用流程 |
| 2 | 内容 IR | Stable | 同上 |
| 3 | 文档类型档案 / 领域模型 | Stable（字段） / Evolving（语义取值） | 语义取值可扩展 |
| 4 | 门禁规则集 | Evolving | 规则可增删，判定语义保持 |
| 5 | 渲染策略插件 | Beta | 接口可能调整，改动记入 CHANGELOG |

格式版本由各家族**独立**管理（`contracts.base.FORMAT_CURRENT`），主版本不同
即拒绝加载并给出迁移指引（需求 10.6）。

## 备选方案与取舍

| 方案 | 优点 | 代价 | 结论 |
| --- | --- | --- | --- |
| 全部承诺 Stable | 使用者放心 | 早期无法演进，背上不必要负担 | 否 |
| 全部不承诺 | 演进自由 | 无人敢用 | 否 |
| **分级承诺（采纳）** | 核心稳定、外围可演进 | 需要逐份文档写清每级允许的变更 | 采纳 |

## 后果

### 正面

- 契约层可被第三方安全依赖（前端已直接消费其 JSON Schema）；
- 外围扩展点保留演进空间，不必为早期设计错误买单。

### 负面（明确接受的代价）

- 分级边界需要持续维护；新扩展点必须先归类，否则会默认变成"事实上的 Stable"。

### 需要后续跟进

- `docs/spec/` 下逐份文档声明自身稳定度；
- 稳定度变更（尤其降级）必须走 L4 流程并记 ADR。
