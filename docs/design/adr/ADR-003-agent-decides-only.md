# ADR-003 Agent 只做决策，不做 OOXML 操作

- 状态：Accepted
- 日期：2026-09-17
- 关联：需求 4.1 决策三、5.3、5.5；设计 DD-1.1、DD-12

## 背景

模型的输出是概率性的。如果让 Agent 直接写 OOXML（改样式、插表格、算列宽），
那么一次幻觉就会破坏样式保真——而样式保真恰恰是本项目的首要承诺。

代价与收益严重不对称：模型直写能省下的开发量，远小于一次样式损坏造成的返工
与信任损失。更麻烦的是，损坏往往**不可复现**（同一输入两次结果不同），
门禁也就无从下手。

## 决策

Agent 层的职责边界锁定为**决策**：

- 决策内容：从候选集中选哪个原型、哪个样式、哪条规则更适用；
- 表现形式：结构化输出（受限解码）+ 置信度 + 理由，落库为 `Decision` / `ModelCall`；
- **工具面不注册任何 OOXML 直写工具**；所有落笔动作由 `render` 层按确定性算法执行；
- 低置信（低于阈值）不得自动采用，必须进裁决队列。

## 备选方案与取舍

| 方案 | 优点 | 代价 | 结论 |
| --- | --- | --- | --- |
| Agent 直写文档 | 灵活，可处理非结构化排版 | 破坏样式保真；不可复现；难以门禁 | 否 |
| **Agent 只决策（采纳）** | 决策可留痕、可复核、可回放；落笔确定；模型不可用时可退化为规则 | 需为每类决策设计候选集与降级路径；表达能力受候选集限制 | 采纳 |

## 后果

### 正面

- 模型不可用时，规则默认值可顶上，**构建不失败**（NFR-26 / 验收 39）；
- 每一次决策都可追溯：谁做的、依据什么、置信度多少、是否走了兜底；
- 落笔动作是纯函数式的，可做确定性测试。

### 负面（明确接受的代价）

- 候选集设得不好，模型选不出好结果——表达能力天花板由候选集决定；
- 需要额外维护"决策点 → 候选集 → 阈值 → 降级路径"这套配置。

### 需要后续跟进

- 工具注册表白名单校验（新增工具必须显式登记为白名单）；
- `import-linter` 禁止 `docfidelity.agents` import `docfidelity.ooxml`；
- 决策点分级表（DD-5.2.3）需随实现迭代补齐阈值。
