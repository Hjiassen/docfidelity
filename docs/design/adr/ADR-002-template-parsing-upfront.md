# ADR-002 模板解析前置到入库流程，生成期只查契约

- 状态：Accepted
- 日期：2026-09-17
- 关联：需求 4.1 决策二、4.4；设计 DD-1.1、DD-7、DD-7.2

## 背景

「样式保真」的含义是：产物中与样式相关的部分，与模板原件**逐字节等价**。
要做到这一点，生成期就不能做任何"读模板 → 判断 → 写产物"的动作——因为
判断本身依赖当次解析结果，而解析行为会随库版本、文档复杂度、缓存状态变化。

同时，解析成本随模板规模增长（大型模板的样式表可达数千条目）。若每次构建
都解析一次，构建时间会随文档份数线性放大。

## 决策

模板解析**全部**发生在入库阶段（`registry.ingest`），产出持久化的**模板包**：

```
模板原件.docx ──解析──▶ 模板包（契约 + 块 + 占位符 + 指纹）──入库
                                        │
生成期 ──── 只读 ContractQuery ─────────┘
```

生成期不得重新解析模板，也不得与模板原件比对。

## 备选方案与取舍

| 方案 | 优点 | 代价 | 结论 |
| --- | --- | --- | --- |
| 生成期实时解析模板 | 无入库步骤，链路短 | 生成行为不确定；无法预先回答"这个模板能提供什么"；解析失败暴露在构建后期 | 否 |
| **解析前置入库（采纳）** | 生成期纯确定性；契约可评审、可 diff、可版本化；解析失败在入库时暴露 | 多一步入库；pipeline 阶段数增加 | 采纳 |

## 后果

### 正面

- 生成期是**纯确定性**的：同一模板包 + 同一事实包 → 产物结构一致（幂等可验证）；
- 模板契约可被人阅读、评审、diff，模板升级的影响可提前评估；
- 大模板只解析一次，构建时间与文档份数解耦。

### 负面（明确接受的代价）

- 模板更新必须重新入库，不能"直接替换文件"；
- 契约与原件存在不同步的可能——靠 `package_hash` + 分区指纹比对来发现。

### 需要后续跟进

- 单测断言：生成链路的调用栈中**不出现** `TemplateParser`；
- 集成测试：同一模板连续构建 3 次，产物结构指纹一致（验收 26 的落地方式）。
