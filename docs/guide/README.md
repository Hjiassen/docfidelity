# 使用指南

## V2 阶段入口

M0/M1 已实现有效模板核心与 API，新工作台与模型正文生成分别在 M3、M2。下方浏览器与档案流程属于旧链路；V2 不要求档案或领域模型。接口试用及保存规则见 [有效模板 API](effective-templates.md)。

## 第一次构建

Python 3.11–3.12，在仓库根目录安装后运行自制示例：

```bash
python -m pip install -e .
python examples/build_demo.py
```

生成 `api-sectioned`、`api-summary`、`procedure-sop` 三份文档。只运行其中一份用 `--only procedure-sop`；更换输出根用 `--root var/my-demo`。默认关闭 Office 与模型，输入工作簿由固定内容生成，运行时不访问模型网络。

`var/examples/jobs/<job_id>/artifacts/` 存 DOCX，`work/report.json` 存门禁报告，工作区也保存事实快照、内容 IR 和事件。相同输入会复用有效阶段断点；验证独立重复构建时使用不同输出根。

## 浏览器工作台

安装 `.[server]` 并构建前端，启动方法见 [README](../../README.md)。持久化部署见 [部署说明](../../deploy/README.md)。

1. 在模板库上传可信 `.docx`，检查解析、样式、结构与槽位结果后登记版本。
2. 在模板库登记领域模型与文档类型档案；自制样例见 `examples/domains.json` 和 `examples/profiles/*.json`。
3. 创建项目、登记事实来源，在项目配置关联已登记的模板版本、档案和来源。
4. 运行前置检查并提交构建；作业详情展示阶段进度、失败原因和待裁决项。
5. 阅读门禁报告，处理阻断项与待确认项。产物可以用于检查，存在阻断或待确认时不能视为已定稿。

“一键创建演示项目”使用随发行版分发的自制资产，准备两份模板、领域模型、三份档案和每项目独立的示例来源。创建后可直接在作业页构建三份文档；已有同名资产内容冲突时会拒绝初始化并给出补救动作。普通项目的 `demo-init` 端点使用同一套发行资产；已有配置原样保留。

## 档案与适配

模板包由入库生成，生成期只读取契约和深拷贝基底，禁止重新解析模板。档案声明章节、分组、投影、列和命名；领域模型声明事实对象的字段与展示语义。

新文档类型在以下条件满足时可仅通过配置接入：事实能映射到已有领域对象与连接器；结构能由现有投影表达；呈现能使用已支持的原型。新增连接器或渲染策略属于代码扩展，不应宣传为所有类型都能零代码适配。

模板包、档案及 Content IR 的字段见 [格式规范](../spec/README.md)。修改配置优先复制自制示例并检查 schema；不要手改生成的模板包指纹。

## 模型与降级

```bash
python -m pip install -e ".[server,model]"
```

在服务端环境配置 `DOCFIDELITY_MODEL_ENABLED=true`、`DOCFIDELITY_MODEL_BASE_URL` 和 `DOCFIDELITY_MODEL_NAME`；端点通常包含 `/v1`，且须支持 Chat Completions。密钥使用 `DOCFIDELITY_MODEL_API_KEY`，不得写进项目配置或问题附件。配置变量见 [样例](../../.env.example)。

模型参数量、量化方式与部署位置不限；端点必须由使用方显式配置且授权，调用内容与脱敏范围符合数据边界。模型默认关闭，禁止隐式云端回退与 SDK tracing 外发；本轮真实验收沿用当前 `.env` 模型。

```bash
python scripts/run_baseline.py --model YOUR_MODEL --base-url http://127.0.0.1:8001/v1
```

项目在 P07 调整某个决策点后，将相同路由配置写成 JSON，用于评测。不提供置信度的端点可显式为章节落位选择独立校验：

```json
{
  "model_enabled": true,
  "decision_points": {
    "placement.section_slot": {"admission_policy": "independent_validation"}
  }
}
```

```bash
python scripts/run_baseline.py --routing project-routing.json --model YOUR_MODEL --base-url http://127.0.0.1:8001/v1
```

`--routing` 也支持读取导出的完整项目配置 JSON，自动取其中的 `routing` 对象。它与 `--confidence-threshold` 互斥；后者修改全部模型点，不能代替项目的单点配置。评测命令与服务共用配置来源：进程环境变量及当前目录的 `.env`，环境变量优先；在相同部署目录运行可保持默认报告落点一致。自定义 `--cases` 的报告用于独立评测，生产准入仍要求当前内置样本集的指纹。

基线报告默认写到服务端存储根的 `baseline.json`。决策会话检查模型、端点、样本集与路由配置指纹；旧报告缺少端点指纹也须重测。身份不匹配、未覆盖或未达门槛的点回退规则并标待确认。评测器可显式运行未准入的模型，以便建立第一份基线。报告包含逐点通过率、采用回答的正确率、降级、缺置信度次数及重试累计用量。

缺失置信度不等于高置信度，阈值为 0 仍会默认回退。`independent_validation` 只支持章节落位，检查内容引用、完整候选路径和冻结的兼容槽位；语义正确率仍须通过基线门槛，详见 [需求 5.2](../需求/需求.md)。其他模型决策点未达标时继续由规则接管，不妨碍已经达标的点运行。

默认 compose 阶段为省略 `ProjectionSpec.slot` 的内容选择候选章节；显式绑定的发行示例仍走确定性路径。候选来自档案中的唯一兼容槽位，不会创建新章节；关闭模型、调用失败或待确认时按骨架顺序落位，报告与裁决队列保留待办。没有候选时保留未落位告警。模型只能选择落位，不改写内容和样式。

2026-10-13 当前 `.env` 模型在上述独立校验策略下，章节落位 10/10 达标，另外 8 条其他决策样本因缺置信度回退。真实默认构建采用 5 次落位结论并保留 DOCX，调用与准入依据可在事件及报告 `decisions` / `model_calls` 中复核；置信度保持未知。该小样本结果不代表任意模板与内容的正确率，切换模型、端点或策略后须重新评测。

P13 修改影响之后提交的作业，已提交作业使用保存的非秘密模型配置；独立 worker 的密钥仍从其服务端环境读取。设置页修改不写回 `.env`，重启后恢复部署配置；需要持久变更时同步修改部署配置。

实际排版页数与目录页码需要 Word 或外部排版环境；无 Office 时目录域标记为待刷新。结构快照的分页符数量不能代替实际页数。

## 常见问题

| 现象 | 检查 |
| --- | --- |
| 构建前置检查失败 | 配置引用的模板版本、档案、领域模型与来源是否已登记；查看返回的补救建议 |
| `stages` 为空 | 在仓库根执行安装，确认 `docfidelity stages` 列出五个阶段 |
| 有 DOCX 但报告未通过 | 先查阻断项、来源追溯与裁决队列；文件存在不等于可交付 |
| Windows 中文解码失败 | 设置 `PYTHONUTF8=1` 后重新启动命令 |
| 重启后项目消失 | 默认内存仓储不持久化；配置数据库并先执行迁移 |
| 模型没有被调用 | 发行参考阶段当前没有模型决策调用；扩展阶段再检查总开关、端点、模型标识、SDK 及匹配基线 |

问题复现只使用自造或脱敏数据，报告方式见 [安全策略](../../SECURITY.md) 与 [贡献指南](../../CONTRIBUTING.md)。
