# 验收与已知缺口

本页说明证据边界，不保存容易过时的“全部通过”表。45 条需求对应关系在 `scripts/acceptance_items.py`，判定实现为 `scripts/acceptance_check.py`。

```bash
python scripts/acceptance_check.py
python scripts/acceptance_check.py --with-tests
python scripts/acceptance_check.py --json
python scripts/acceptance_check.py --with-tests --require-complete
```

`PASS` 表示该脚本实际检查通过，`FAIL` 为失败，`SUITE` 仅列出未运行用例，`MANUAL` 需要额外环境或人工证据。脚本退出码 0 只表示没有自动失败，**不表示所有验收项已通过**。测试用例与源码扫描各自仅证明覆盖的行为。

`--require-complete` 在存在 `SUITE` 或 `MANUAL` 时也返回非零，可用作发布前的完整性检查。人工证据须经维护者审核后再更新条目的判定方式，不应删除需求或改成文件存在检查。

## 2026-10-08 审查修订

已发现并修复 CI 缺依赖、基础安装拉入 Web 栈、模型基线准入与身份失配、作业提交输入漂移、模型开关捕获旧值、数据库日志暴露凭据及样式门禁漏检。各修复由回归用例和分发检查覆盖，实际数量以最新测试输出为准。

本机使用真实阶段实现、SQLite 和关闭模型的浏览器工作台，已验证上传与模板登记、来源绑定、配置修改、构建、裁决、下载、排队重启恢复及 compose 故障后的阶段续跑。最终容器还通过页面登记新上传的自制示例模板与配套档案，保存配置后构建下载，并重复构建、核对归一化结构一致；发现并修复版本档案引用被预检误判未登记的问题。这不代表任意新模板无需配置即可构建。

独立 API / worker 原使用各自内存事件索引，造成事件不可见及重复序号。服务端改用锁内持久化读写；独立实例、重启与真实多进程写入由回归覆盖。容器实测进一步核对了 SSE 连续序号、终态收尾、`Last-Event-ID` 补推及重启前后报告、下载与事件的一致性。

新增系统执行锁与中断收尾恢复，覆盖取消阶段仍在写产物、父作业部分失败、API 独立重启及 worker 进程退出。活动作业的重试与续跑受同一把锁保护，非法操作不删除断点，批量重跑加锁后重读子作业状态。部署自检脚本已在真实容器中构建并下载三份文档；本机结果不替代远端 CI。

需求修订澄清了结构保真、安装后离线、模型出口、实际页数与源快照的边界。保留需求、设计、ADR、Schema 和运行指南；重复开发轮次说明与旧截图从工作树移除，仍可在 Git 历史追溯。

正式退出 P0 必须补齐上述证据，不能用静态清单或 API 夹具替代浏览器、容器与真实模型验收。
